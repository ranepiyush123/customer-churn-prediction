# Customer Churn Prediction API

A portfolio project combining **data science and software engineering**: train and compare classification models, then serve churn predictions through a validated REST API.

> **Important:** This project uses **synthetic customer data**, generated by a defined statistical process. Metrics demonstrate the software workflow and **must not be interpreted as real-world customer churn performance**.

## Features

- Reproducible synthetic data generator with a fixed random seed
- Preprocessing pipeline with numeric scaling and categorical encoding
- Logistic Regression and Random Forest model comparison
- Stratified 80/20 holdout evaluation using accuracy, precision, recall, F1, and ROC-AUC
- Automatic selection of the model with the highest holdout ROC-AUC (for demonstration; a separate validation/test split would be required for an unbiased final performance estimate)
- FastAPI `/predict` endpoint with Pydantic validation and interactive API docs
- Unit tests, GitHub Actions CI, and Docker support

## Tech stack

Python, Pandas, NumPy, Scikit-learn, FastAPI, Pydantic, Pytest, Docker, GitHub Actions.

## Quick start

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
python -m src.train
uvicorn src.api:app --reload
```

Open **http://127.0.0.1:8000/docs** to try the API.

### Example request

```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H 'Content-Type: application/json' \
  -d '{"tenure_months": 8, "monthly_charges": 95.0, "support_tickets": 4, "contract_type": "monthly", "autopay": "no"}'
```

Response fields: `churn_probability`, `predicted_churn`, `risk_level`.

## Responsible interpretation and next steps

This is a **demonstration application**, not a production churn prediction service. Before deploying on real data, use an appropriately licensed dataset, leakage checks, chronological or suitable out-of-time evaluation, calibration, fairness and privacy reviews, model monitoring, and retraining plans. Model selection currently uses the holdout set, so reported performance is not an independent final test estimate.
